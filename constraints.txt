# Locked resolution of every Python package in the runtime image.
#
# WHY THIS FILE EXISTS
# --------------------
# requirements.txt lists most of its packages by bare name, with no version.
# A bare name means "whatever PyPI is serving on the day you build", so two
# builds of the same commit produce different images. On 2026-08-25 a rebuild
# picked up mcp 2.1.1 (published three hours earlier), whose Server class had
# dropped list_tools() and renamed streamablehttp_client. Four built-in MCP
# servers and every remote HTTP MCP server stopped working, from a rebuild
# that was only meant to ship an unrelated UI fix.
#
# This file pins the full resolution — direct and transitive — so a rebuild
# reproduces the set that is known to work rather than re-rolling the dice.
# It constrains only the requirements.txt/-optional.txt install in Dockerfile;
# the patched Real-ESRGAN wheels install with --no-deps in their own layer and
# are deliberately absent here.
#
# HOW TO REGENERATE
# -----------------
# Only from an image whose servers have been verified to actually start:
#
#   docker run --rm --entrypoint pip odysseus-odysseus:latest freeze \
#     | grep -v ' @ file://' > constraints.txt
#
# then restore this header. Do not hand-edit a version to move it forward:
# raise the bound in requirements.txt, rebuild, verify, and re-freeze.
#
# Captured from odysseus-odysseus:latest, built 2026-08-25, verified by a real
# stdio initialize + list_tools handshake against all four built-in servers.
